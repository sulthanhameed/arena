## 🧭 Architecture

```
            ┌──────────────────────────────────────────┐
            │   React 19 + Vite  (Vercel / any CDN)    │
            │   @supabase/supabase-js                  │
            └───────────────┬──────────────────────────┘
                            │  HTTPS + JWT
         ┌──────────────────┼────────────────────┐
         ▼                  ▼                    ▼
┌─────────────────┐ ┌────────────────┐ ┌─────────────────────┐
│ Supabase Auth   │ │  PostgREST     │ │  Edge Functions     │
│ sign-up / in    │ │  tables + RPC  │ │  (Deno, global)     │
│ sessions, JWT   │ │                │ │  Razorpay / Stripe  │
└────────┬────────┘ └───────┬────────┘ └──────────┬──────────┘
         │                  │                     │
         └──────────────────┼─────────────────────┘
                            ▼
              ┌─────────────────────────────┐
              │  PostgreSQL                 │
              │  · 9 tables, 5 enums        │
              │  · Row Level Security       │
              │  · triggers + RPC functions │
              └─────────────────────────────┘
```

**The business logic lives in the database.** Pricing, order numbers, status
history, review aggregates and authorisation are all enforced by Postgres, so
there is no API server that could be bypassed — or that you have to keep
awake on a free Render dyno.

### What moved where

| Before (Express + Mongo + Render) | Now (Supabase) |
|---|---|
| `POST /api/auth/signup` · `login` | `supabase.auth.signUp()` / `signInWithPassword()` |
| `middleware/auth.js` → `protect` | Supabase Auth JWT + `auth.uid()` in RLS policies |
| `middleware/auth.js` → `adminOnly` | `public.is_admin()` used by policies & RPCs |
| `models/*.js` (Mongoose) | `supabase/migrations/*.sql` (real DDL) |
| `GET /api/products` | `from('products').select(...)` + RLS |
| `POST /api/orders` | `rpc('create_order')` — `SECURITY DEFINER` |
| `GET /api/orders/track/:id` | `rpc('track_order')` — callable by `anon` |
| `PUT /api/orders/:id/status` | `rpc('set_order_status')` — admin only |
| `POST /api/reviews` | `rpc('submit_review')` |
| `paymentController.js` | `supabase/functions/razorpay-*`, `stripe-*` |
| `utils/notifications.js` (Nodemailer/Twilio) | `supabase/functions/_shared/notify.ts` (Resend/Twilio REST) |
| `render.yaml`, `Dockerfile`, `docker-compose.yml` | `supabase/config.toml` + `supabase db push` |

## 🚀 Quick start

### Prerequisites

- Node.js 18+
- [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started)
  (`npm install -g supabase`) — needs Docker for the local stack
- A Razorpay / Stripe test account (optional)

### 1. Start the database

```bash
supabase start      # Postgres + Auth + PostgREST + Studio + Storage
supabase db reset   # apply supabase/migrations/* then supabase/seed.sql
```

`supabase start` prints your local URL and `anon` key.

### 2. Point the frontend at it

```bash
cp .env.example .env
#   VITE_SUPABASE_URL=http://127.0.0.1:54321
#   VITE_SUPABASE_ANON_KEY=<anon key printed above>

npm install
npm run dev         # → http://localhost:5173
```

### 3. (Optional) Run the payment functions

```bash
cp supabase/.env.example supabase/.env   # add Razorpay / Stripe keys
npm run functions:serve
```

Sign in with **`admin@khang.com` / `admin123`** to open the admin dashboard.

> Leave `.env` empty and the site still runs — it falls back to an offline
> demo mode with the static menu and a simulated checkout.

## 🎨 Frontend

**React 19 · TypeScript · Vite 7 · Tailwind CSS v4**

- ✨ Interactive 5-dish hero swap
- 🎬 Scroll-triggered reveals (IntersectionObserver, no animation library)
- 🍱 Editorial menu with category filter + sort
- 🛒 Cart drawer — subtotal · 5% tax · free delivery over ₹500
- 💳 Real Razorpay popup / Stripe intent via Edge Functions
- 👤 **Supabase Auth** — sessions persist and refresh automatically
- 🚚 **Live order tracking** — public `track_order()` RPC, no sign-in needed
- ⚡ **Admin dashboard** — order management over **Supabase Realtime**

### Where the menu comes from

The storefront reads its dishes from Postgres, not from a bundled array.
`src/context/MenuContext.tsx` is the single source: on mount it pulls
`products` and `categories` over PostgREST (the one thing anon may read
under RLS) and hands them to every component through `useMenu()`.

`src/data/menu.ts` is a **fallback**, not the source of truth. It is used
when `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` are unset, and when a
configured project fails or takes longer than 8 seconds — the page shows
the bundled copy with a notice rather than an empty restaurant or an
indefinite spinner. The seed keeps `products.code` in parity with the
ids in that file so the two never disagree.

To confirm which one you are looking at, the menu section carries
`data-menu-source="supabase | offline"`.

See **[`frontend/README.md`](./frontend/README.md)** for component details.

```bash
npm run dev      # dev server
npm run build    # single-file dist/index.html
npm run db:types # regenerate src/types/database.types.ts from the schema
```

## 🗄 Database

**PostgreSQL 15 (Supabase)** — 9 tables, 5 enum types, Row Level Security on
every one of them.

| Table | Purpose |
|---|---|
| `profiles` | mirror of `auth.users` (name, phone, role) |
| `addresses` | saved delivery addresses |
| `categories` | 5 menu categories |
| `products` | 17 dishes + `tsvector` search column |
| `orders` | one row per order, `KH-2026-1042` numbering |
| `order_items` | cart lines, `line_total` generated column |
| `order_tracking` | append-only status history |
| `reviews` | one review per diner per dish |
| `favourites` | join table |

Full docs: **[`database/README.md`](./database/README.md)** ·
**[ER diagram](./database/docs/ER-DIAGRAM.md)** ·
**[indexes](./database/docs/INDEXES.md)** ·
**[RLS policies](./database/docs/RLS-POLICIES.md)**

### Business rules enforced by Postgres

| Rule | Mechanism |
|---|---|
| Order totals are never taken from the client | `create_order()` prices the cart from `products`; there is **no INSERT policy** on `orders` |
| A user only ever sees their own orders | `using (user_id = auth.uid() or public.is_admin())` |
| Only admins change order status | `set_order_status()` raises unless `is_admin()` |
| Nobody promotes themselves to admin | `guard_profile_role()` trigger |
| A profile exists for every auth user | `handle_new_user()` trigger on `auth.users` |
| Product ratings always match their reviews | `refresh_product_rating()` trigger |
| Status changes are auditable | `log_status_change()` writes `order_tracking` |

### Seed data

- **5 categories** — Dim Sum · Noodles & Soups · Rice & Curry · Snacks · Drinks
- **17 dishes** with prices, Chinese names, ingredients and images
- **1 admin** — `admin@khang.com` / `admin123` (a real Supabase Auth user)

## ⚡ Edge Functions (the "backend")

Six Deno functions in `supabase/functions/`, deployed globally — they only
exist for work that genuinely needs a secret key.

| Function | Replaces | JWT |
|---|---|---|
| `razorpay-create-order` | `POST /api/payments/razorpay/create-order` | required |
| `razorpay-verify` | `POST /api/payments/razorpay/verify` | required |
| `stripe-create-intent` | `POST /api/payments/stripe/create-intent` | required |
| `stripe-webhook` | `POST /api/payments/stripe/webhook` | **off** (Stripe signs instead) |
| `refund-order` | `POST /api/payments/refund` | required + admin |
| `notify-order` | the fire-and-forget email/SMS on COD | required |

```bash
npm run functions:serve                      # run them locally
npm run functions:deploy                     # deploy all
supabase functions deploy stripe-webhook     # or just one
supabase secrets set --env-file supabase/.env
```

Everything else — menu, reviews, order history, admin lists — goes straight
from the browser to PostgREST, guarded by RLS. No function needed.

## 💳 Payment integration

**Real payment gateways** — not simulated.

| Method | Gateway | Notes |
|---|---|---|
| 📱 UPI | Razorpay | GPay, PhonePe, Paytm, BHIM |
| 💳 Cards | Razorpay / Stripe | Visa, Mastercard, RuPay, Amex |
| 👛 Wallets | Razorpay | Paytm, Mobikwik, Freecharge |
| 💵 COD | — | confirmation email/SMS via `notify-order` |

### End-to-end flow (Razorpay)

```
1.  User clicks "Pay ₹609 Securely →"
2.  supabase.rpc('create_order')           → Postgres prices the cart,
                                             returns KH-2026-1042 (pending)
3.  functions.invoke('razorpay-create-order')
       ↳ amount read from the orders row, never from the browser
       ← { key, razorpay_order_id, amount, currency, customer }
4.  checkout.razorpay.com widget opens, pre-filled and themed
5.  User pays (test card 4111 1111 1111 1111 · OTP 1234)
6.  functions.invoke('razorpay-verify')
       ↳ HMAC-SHA256(order_id|payment_id, key_secret) via Web Crypto
       ↳ rpc('mark_order_paid')  [service_role only]
       ↳ Resend email + Twilio SMS
7.  ✅ success screen · admin dashboard updates live over Realtime
```

### Razorpay setup

1. Sign up at [razorpay.com](https://razorpay.com) → **API Keys → Generate Test Key**
2. `supabase/.env`:
   ```env
   RAZORPAY_KEY_ID=rzp_test_xxx
   RAZORPAY_KEY_SECRET=your_secret
   ```
3. `supabase secrets set --env-file supabase/.env`
4. Test card `4111 1111 1111 1111` · any future expiry · CVV `123` · OTP `1234`

### Stripe setup

1. [stripe.com](https://stripe.com) → **Developers → API Keys**
2. Add `STRIPE_SECRET_KEY` / `STRIPE_PUBLISHABLE_KEY` to `supabase/.env`
3. Local webhooks:
   ```bash
   stripe listen --forward-to http://127.0.0.1:54321/functions/v1/stripe-webhook
   ```
   Copy the printed `whsec_…` into `STRIPE_WEBHOOK_SECRET`
4. Production webhook endpoint:
   `https://<project-ref>.supabase.co/functions/v1/stripe-webhook`
5. Test card `4242 4242 4242 4242`

### Security

- **HMAC-SHA256 verification** of every Razorpay payment (Web Crypto, constant-time compare)
- **Stripe signatures** verified with `constructEventAsync` + SubtleCrypto
- **Totals recalculated in SQL** — a tampered cart cannot change the price
- **Idempotent capture** — `mark_order_paid()` keeps the first `paid_at`
- **`service_role` never reaches the browser** — only Edge Functions hold it
- **Refunds** are admin-only, enforced by `requireAdmin()` *and* RLS

## 🌐 Deployment

| Layer | Platform | Config |
|---|---|---|
| **Frontend** | Vercel / Netlify / any static host | `vercel.json` |
| **Database + Auth + API** | Supabase (free tier) | `supabase/migrations/` |
| **Edge Functions** | Supabase (global, included) | `supabase/functions/` |

There is no separate server to deploy, so no Render/Railway/Fly step, no
Dockerfile, and no cold-starting free dyno in front of your menu.

### 1. Database → Supabase

```bash
supabase link --project-ref <your-project-ref>
supabase db push                                 # run all migrations
psql "$SUPABASE_DB_URL" -f supabase/seed.sql     # load the menu (optional)
```

### 2. Edge Functions → Supabase

```bash
supabase secrets set --env-file supabase/.env
supabase functions deploy
```

### 3. Frontend → Vercel

```bash
vercel --prod
```

Set these environment variables in the Vercel project:

```env
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon public key>
```

### 4. Lock it down

- *Authentication → URL Configuration* → set **Site URL** to your Vercel domain
- *Authentication → Providers → Email* → turn **Confirm email** on
- `supabase secrets set CLIENT_URL=https://your-domain.com` (CORS allow-list)
- Promote your own account:
  ```sql
  update public.profiles set role = 'admin' where email = 'you@example.com';
  ```
- Delete the seeded `admin@khang.com` user

## 🔒 Security summary

- Credentials handled by **Supabase Auth** (bcrypt, rotation, MFA-ready) — the
  app database has no password column at all
- **Row Level Security on all 9 tables**; the anon key alone exposes only the menu
- **`SECURITY DEFINER` RPCs** are the only write path for orders
- **Privilege-escalation guard** trigger on `profiles.role`
- **Payment signatures** verified server-side (Razorpay HMAC, Stripe webhook)
- **CORS allow-list** per Edge Function via `CLIENT_URL`
- `service_role` key lives only in Edge Function secrets
- Rate limiting, DDoS protection and TLS handled by the Supabase edge
